# Database design

`CrmDbContext` is the production persistence context and derives from `IdentityDbContext<CrmUser, IdentityRole<int>, int>`. EF Core SQL Server configurations are in `Backend/MiniCRM.Infrastructure/Configurations/EntityConfigurations.cs`; migrations are checked into `Backend/MiniCRM.Infrastructure/Migrations`.

The schema covers ASP.NET Core Identity, customers, contacts, leads, opportunities, CRM tasks, notes, activities, hashed refresh tokens, and revoked JWT identifiers. Fluent configurations define normalized unique email indexes, lookup/assignment indexes, lengths, decimal precision, check constraints, UTC timestamp defaults, foreign keys, and delete behavior. Lead conversion runs in a SQL transaction. Refresh tokens are stored as hashes, rotated on refresh, and revoked on reuse.

The initial and token revocation migrations have been generated, but not applied. The default SQL Server instance is running at localhost:1433. Its SuperSocketNetLib configuration reports no assigned certificate thumbprint; the localhost certificate in the machine personal store is self-signed and untrusted. More fundamentally, Windows SChannel client credential acquisition fails for public HTTPS as well as SQL TLS (`SEC_E_NO_CREDENTIALS`). The environment denies access to the system Schannel/instance configuration needed to repair this. The project retains `Encrypt=True;TrustServerCertificate=False`; secure database migration and CRUD verification must wait until the host TLS client is repaired and SQL Server presents a trusted, name-matching server certificate.
